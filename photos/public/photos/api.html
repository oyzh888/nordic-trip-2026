📷 共享相册 · API 文档

北欧 2026 共享相册（nordic.airacle.com/photos/）的上传 / 下载接口 · 给脚本、命令行、自动化用

一句话：在相册网页里生成一个密钥，然后一条命令把电脑上的整个文件夹传上来 —— 断点续传、自动去重（相册里已有的不会再传）、原图原样传（HEIC / RAW / Live Photo 都行），网页能做的这里都能做。

1. 三分钟上手

① 拿密钥

打开 相册 → 右上「＋ 上传」→ 展开「🔑 用脚本 / 命令行批量传」→「＋ 生成一个密钥」。 密钥长这样：np_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx，只显示一次，复制好。

密钥 = 你本人：用它传的照片记在你名下，和你在网页上传的一模一样。别发到群里；不用了在同一个地方点「撤销」，马上失效。

② 一条命令传整个文件夹（推荐）

curl -O https://nordic.airacle.com/photos/np_upload.py      # 只用 Python 标准库，不用装任何东西
export NP_KEY=np_你的密钥
python3 np_upload.py ~/Pictures/冰岛                         # 文件夹会递归进去
python3 np_upload.py -j 8 /Volumes/SD卡/DCIM ~/Desktop/a.HEIC  # 多个路径、8 个文件同时传
  • 只传照片 / 视频 / 相机 RAW，其它文件（.AAE、.DS_Store…）自动跳过
  • 中断了就重跑同一条命令：传过的秒跳过，传一半的大视频只补缺的块
  • Live Photo（同名的 .HEIC + .MOV）原样传上来，相册自动配成一张会动的照片

③ 或者用 curl 一个一个传（≤ 8 MB 的文件）

curl -X PUT -H "Authorization: Bearer $NP_KEY" \
     --data-binary @IMG_1234.HEIC \
     "https://nordic.airacle.com/photos/api/upload/file?name=IMG_1234.HEIC"
# → {"h":"9f2c…","status":"uploaded"}     已经有了 → "status":"exists"

2. 鉴权

所有接口都在 https://nordic.airacle.com/photos 下，请求头带：

Authorization: Bearer np_你的密钥

没带 / 密钥不对 / 已撤销 → 401 {"error":"login"}。浏览器里登录后的 cookie 也能调同样的接口。

版本：/api/v1/… 和 /api/… 现在是同一套。写新的前端 / 工具请用 /api/v1/ —— 以后有不兼容的改动会开 v2，v1 不动。

3. 上传

内容 ID（h）

每个文件用内容算一个 ID：把文件按 8 MB 切块，每块算 SHA-256，把这些 32 字节的摘要依次拼起来，再算一次 SHA-256，取十六进制。 同样的字节 = 同样的 ID → 秒传；服务端会用收到的块自己复核一遍，对不上就拒收。

import hashlib
def content_id(path):
    shas = []
    with open(path, 'rb') as f:
        while b := f.read(8 * 2**20): shas.append(hashlib.sha256(b).digest())
    return hashlib.sha256(b''.join(shas)).hexdigest()
接口做什么请求返回
POST /api/upload/probe先整批问「这些相册里有没有」—— 按文件名 + 字节数，不用读文件 {"items":[["IMG_1.HEIC",2345678],…]}（一次 ≤ 5000）{"hit":[0,3]} = 第几个已经有了（顺带记在你名下）
PUT /api/upload/file?name=…一步上传，适合 ≤ 8 MB 的照片body = 文件字节；可选 &taken=2026-09-27T22:14:05（没 EXIF 时用） {"h","status":"uploaded"|"exists"}
POST /api/upload/init分块上传 ①：登记{"h","size","name","type","crc"}（crc = 整个文件的 CRC-32，打包下载用） {"status":"upload","nparts","psize","done":[已收到的块号]} · "exists" = 秒传 · "wait" = 别处正在传同一个，3 秒后再问
PUT /api/upload/part?h=…&n=1分块上传 ②：传第 n 块（从 1 开始，每块 8 MB，最后一块是余数）body = 块字节；可选头 x-part-sha256{"ok":true}；大小不对 400，哈希不对 422
POST /api/upload/complete分块上传 ③：收尾{"h"} "done" · "missing"+done（补缺的块再 complete）· "corrupt"（重新算 ID 再传）

断点续传就是：再 init 一次，服务端返回 done，只传不在里面的块。块之间可以并行。传完之后 GPU 端会在几分钟内补上缩略图、描述、人脸、地点、拍摄地当地时间。

4. 浏览 / 下载

接口做什么
GET /api/me当前身份 {"user":{"id","name"}} —— 拿来验密钥
GET /api/list?since={ver}增量：只给 ver 那一版之后变了的 → {"ver","delta":true,"items":[…],"gone":[h…]}（用户 / 人物 / 时刻这几张小表变了才带）。 合并：gone 里的拿掉，items 里已有的原地替换、没有的接在后面。答不了的时候（服务端重启过、中间改动太多）直接回全量 —— 看有没有 delta 字段就行。 轮询请用这个：相册 1.4 万张时全量是 1.7 MB，增量通常几百字节到几 KB
GET /api/list整个相册的元数据（全量，支持 If-None-Match → 304；加 ?stale=1 可以拿几分钟前拼好的那份，之后马上用 since 补齐）。每项：h ID · n 文件名 · k i照片/v视频 · t 拍摄地当地时间 · s 字节 · pl 地点 · la/lo GPS · cam 相机 · cap AI 描述 · tg 标签 · u 上传者 id · p 照片里的人 · lv Live Photo 视频的 ID
GET /api/search?q=极光搜索（关键词 + 以文搜图）→ {"ids":[…]}
GET /f/{h}/o原图 / 原视频（加 ?dl=1 按原文件名下载；支持 Range）
GET /f/{h}/p · /t · /v预览图（长边 1600 JPEG）· 缩略图 · 720p 视频预览
POST /api/zip{"ids":[…]}（≤ 500）→ {"url"}，GET 那个 url 拿到按「日期_地点/」分好文件夹的 zip
POST /api/delete{"h"} 撤回「我传过这张」；没人再认领才从相册里隐藏（Live Photo 连同视频）
# 例：把相册里所有极光照片的原图下到本地
curl -s -H "Authorization: Bearer $NP_KEY" "https://nordic.airacle.com/photos/api/search?q=极光" \
 | python3 -c "import json,sys; print('\n'.join(json.load(sys.stdin)['ids']))" \
 | while read h; do curl -s -OJ -H "Authorization: Bearer $NP_KEY" "https://nordic.airacle.com/photos/f/$h/o?dl=1"; done

5. 密钥管理

接口做什么
POST /api/keys{"name":"家里的 Mac"} → {"id","key"}。只能在登录的网页里调（拿着密钥不能再生新密钥）
GET /api/keys我的密钥列表（名字、创建、最近使用时间；不含密钥本身）
POST /api/keys/revoke{"id"} 撤销，马上失效

6. 支持的格式

照片：JPEG · HEIC/HEIF · AVIF · WebP · PNG · TIFF · GIF · 相机 RAW（CR3 · CR2 · ARW · NEF · DNG · RAF · ORF · RW2 · PEF · SRW…）
视频：MOV · MP4 · M4V · MKV · WebM · AVI · 3GP（HEVC / H.264 / ProRes / AV1）
都原样保存、原样下载；浏览用的预览图 / 视频由 GPU 端统一转成所有浏览器都能看的格式。

7. 限制和错误

情况返回
没登录 / 密钥无效401
一步上传超过 8 MB413 → 用分块接口或 np_upload.py
分块大小不对 / 哈希不对400 / 422
服务端临时错误5xx → 退避重试（np_upload.py 会自动重试 6 次）

单个文件最大约 80 GB（10,000 块 × 8 MB）。

8. 多线程 / 并发

可以多线程同时调，所有接口都是并发安全的。线上实测（2026-10-02，从一台机器发起）：

场景结果
一步上传 3 MB × 192 个，64 线程全部成功 · 162 MB/s · 每秒 54 个文件 · 单个延迟中位 0.8 秒
分块上传 20 MB × 96 个，64 线程全部成功 · 150 MB/s
同一个文件被 32 个线程同时传只存一份；其余返回 exists，或 503 让你稍后重试
  • 大于 8 MB 的文件一定走分块接口（一步上传在服务端要整份算哈希，文件大了会超出每个请求的 CPU 时间）。块之间也可以并行。
  • 遇到 503 / 429 / 网络错误就退避重试（1、2、4、8 秒……）。503 带 retry-after，意思是「同一个文件正在被另一处同时写」，等一下再试就会拿到 exists。
  • 重试是安全的：同样的字节内容 ID 一样，重复 init / part / complete 不会产生重复照片。
  • 建议 16～64 个线程，再多一般不会更快（瓶颈变成你那边的上行带宽）。np_upload.py -j 32 就是 32 线程。
